# Чудо Обувь

Учебное приложение оформления заказов по заданиям 1–4 КИМ 09.02.07-2-2027.

## Организация проекта

Сохранены WPF (.NET 8), XAML + обработчики в code-behind, сущности в Entities и прямое подключение MySQL через EF Core / Pomelo в DbContexts/ChudoobuvContext.cs. Строка подключения осталась прежней. Данные и настройки приложения не перенесены в JSON. Служебные файлы JSON, которые создаёт сам .NET при сборке, не являются хранилищем данных приложения.

Окно OrderWindow используется в двух режимах: корзина и управление заказами. Новые слои, сервисы, отдельный фронтенд или сервер не добавлены. Повторяющийся список изображений в csproj заменён одной маской; логотип встроен как ресурс, остальные изображения копируются в Images.

## Запуск

1. Нужны Windows x64, .NET Desktop Runtime 8 и MySQL 8.0.
2. На текущем компьютере БД уже обновлена, данные восстановлены. Повторно запускать SQL здесь не требуется.
3. Для новой установки откройте общее/chudoobuv.sql в MySQL Workbench и выполните скрипт. Он создаёт БД chudoobuv с данными. При восстановлении существующие одноимённые таблицы заменяются; предварительно сохраните свою БД.
4. Параметры подключения находятся в ChudoObuv/ChudoObuv/DbContexts/ChudoobuvContext.cs; способ подключения сохранён.
5. Откройте ChudoObuv/ChudoObuv.sln в Visual Studio и запустите проект либо используйте подготовленный ChudoObuv.exe. При переносе готовой сборки переносите вместе с ним папку Images.
6. Введите логин из таблицы users или исходного Users_import.xlsx. Пароль не требуется. Кнопка «Посмотреть товары» открывает каталог гостю.

Для обновления другой копии именно исходной БД данного проекта вместо полного восстановления можно один раз выполнить общее/update_orders.sql. Скрипт расширяет ordersitem, восстанавливает исходные 30 строк заказов и добавляет ограничения. На уже обновлённой БД его повторно выполнять нельзя. Для копии предыдущей версии приложения достаточно выполнить только общее/required_stock.sql; полный дамп уже содержит новую схему.

## Возможности

| Роль | Возможности |
| --- | --- |
| Гость | Каталог, изображения, скидочная цена, остатки, карточка товара |
| Авторизованный пользователь | Поиск, категории, сортировка по итоговой цене, корзина, оформление заказа на себя |
| Менеджер | Всё перечисленное; список и состав заказов, новый заказ на выбранного клиента, удаление заказов |
| Администратор | Всё перечисленное; изменение даты заказа, удаление отдельных строк заказа |

Поиск по названию и описанию работает совместно с фильтром категории, а выбранная сортировка сохраняется. Все параметры применяются сразу.

Каталог показывает «много» при количестве более пяти, иначе «мало». При остатке не более трёх карточка имеет фон #FF8080. Пустое или отсутствующее изображение заменяется picture.png. ФИО текущего пользователя отображается справа сверху.

Цена уменьшается на 25%, если на модель не было заказов в предыдущем календарном месяце. Учитывается интервал от первого дня предыдущего месяца включительно до первого дня текущего месяца исключительно. Итог округляется до копеек.

## Оформление и управление заказами

Выберите модель → размер → количество → «Добавить в заказ». Повторите для других товаров. В корзине можно изменить количество, удалить строку, отказаться от заказа или вернуться в каталог. Закрытие корзины оставляет её содержимое до выхода из учётной записи. Выход очищает корзину.

Менеджер и администратор могут выбрать клиента в корзине. Кнопка «Новый заказ из каталога» в управлении возвращает к выбору товаров; оформление завершается через корзину.

При подтверждении приложение повторно читает доступные остатки и цены. Изменение цены требует повторного подтверждения пересчитанной корзины. Создание заказа, строк и списание остатков сохраняются одним вызовом SaveChanges(). Явных BeginTransaction, Commit и Rollback в коде нет; EF Core сам сохраняет изменения одного вызова целиком. Поле stockitems.quantity настроено как IsConcurrencyToken(): если остаток успел изменить другой пользователь, сохранение отклоняется и нужно повторить действие с актуальными данными. При нехватке хотя бы одной позиции заказ целиком отклоняется.

В строке заказа сохраняются модель, размер, количество и цена за пару на момент покупки. Итог вычисляется из этих строк и не меняется при последующем пересчёте каталожной скидки. Удаление заказа возвращает все пары на склад; удаление строки возвращает её количество. Удаление последней строки удаляет заказ. Удаления требуют подтверждения. После операций списки обновляются.

Дата заказа редактируется администратором через календарь; будущая или некорректная дата не принимается.

## База данных и импорт

Сохранены исходные таблицы и их имена. В ordersitem добавлены sizeId, quantity и unitPrice. Размер связан с sizes; количество положительное, цена неотрицательная. В stockitems добавлена уникальность сочетания prodId + SizeId и запрет отрицательных остатков. Поля prodId, SizeId и quantity обязательны (NOT NULL); в C# это обычные int без ?. Данные перед изменением проверены, пропущенных значений не было. Итог заказа и ФИО не дублируются в отдельных новых полях.

В пользовательских CSV старых заказов отсутствовали размер, количество и цена, хотя в оригинальном общее/приложения/Задание 1/Прил_2_ОЗ_КИМ_09.02.07-2-2027/Orders_import.xlsx эти данные есть. Все 30 строк восстановлены по оригиналу с проверкой номера заказа, даты, ФИО, модели, категории и производителя. При сопоставлении учтены неразрывные/концевые пробелы и сокращённое в оригинале название модели «Черные туфли в классическом стиле». Выдуманные размеры и цены не использовались.

Исходные складские остатки сохранены как снимок наличия; исторические заказы повторно из них не вычитались. В комплекте: 31 модель, 10 исходных заказов и 30 строк с полными данными. Полный дамп содержит структуру, ключи, ограничения и данные. ER-диаграмма находится в общее/ER.pdf.

## Проверка

Сборка Debug и публикация Release выполнены успешно. Осталось исходное предупреждение генератора EF о хранении строки подключения в коде; этот способ оставлен по требованию пользователя.

На отдельной копии актуальной MySQL-БД прошла 41 автоматическая проверка. Дополнительно проверены конфликт изменения остатков двумя контекстами, отсутствие частичного заказа после ошибки SaveChanges и переключение режимов окна. Базовые проверки: скидка и округление; обе границы месяца; нулевой остаток; пересчёт изменившейся цены и отсутствие списания до подтверждения; сохранение размера; списание; дата и историческая сумма; отказ при нехватке; откат; возврат остатков; каскадное удаление строк; ограничения гостя; очистка корзины; различие прав менеджера и администратора. Временные тестовые товары и заказы удалены.

Полный дамп восстановлен в отдельную временную БД: получены 31 модель, 10 заказов и 30 полных строк. Скрипт обновления отдельно проверен на копии исходной БД. Временные БД после проверки удалены.

Визуально проверены каталог, пустая корзина и окно управления заказами. Проверен запуск готового ChudoObuv.exe. PDF-диаграмма отрисована и проверена.
